# VOA Player

A player for VOA Special English audio material. It plays an episode while the official transcript is shown and the currently spoken word is highlighted, karaoke style.

## Current status

- Repo: `github.com/axln/voa-player` (public, MIT), `main` branch. Published with GitHub Pages via `.github/workflows/pages.yml` on every push to `main` (https://axln.github.io/voa-player/). Build sets `BASE_PATH=/voa-player`. Latest work: 100 more Learning English episodes (Jan–Mar 2025, 147 in total), timings for all 147 (`npm run align`), dictionary rebuilt with the new transcripts and lemma entries for irregular and comparative forms.
- Scaffold: SvelteKit 3 with TypeScript, Tailwind, ESLint, Prettier, Vitest and Playwright. Uses `adapter-static`, and `src/routes/+layout.ts` prerenders all routes. `npm run build` passes.
- Imports: SvelteKit `$lib` and `#lib` aliases did not resolve in this setup, so app code uses relative imports. `$app/paths` exports `resolve()` and `asset()` here, not `base`.
- Phase 1 (done): sample data for 47 episodes: 10 from 2011 and 37 from 2025. See Data notes.
- Player (built, not deployed): library page with section filters; episode page with the transcript, karaoke highlight, play/pause, skip ±5 s, speed (0.75×–1.5×), click a word to seek, keyboard (space, arrows), auto-scroll, and a settings popup. Auto-scroll puts the spoken word at 40% of the viewport height (`Player.svelte`), so a few lines show below it above the mobile dock. The home page sets its own `<title>`, so it does not keep an episode name after back navigation.
- Highlight rules: a word is highlighted only between its start and end. Words already spoken are dimmed. During a pause of at least 1 s (`LONG_PAUSE` in `Player.svelte`), a yellow underline bar marks the next word. The active word is a plain yellow background that fades in, with no ring or border.
- Word timings: `static/data/timings/<id>.json` is `{ "starts": [...], "ends": [...] }`, one start and one end (seconds) per word, in transcript word order. When the file exists, the player uses it. Otherwise it uses a mock estimate from word length and punctuation (`src/lib/align.ts`) and shows a note.
- Ends: the provider's word end, capped at about 0.25 s plus 0.1 s per letter and never past the next word's start. Without the cap, the aligner stretches a word across a pause.
- Narration vs printed text: the vocabulary list and the credit lines after the sign-off ("reported this story for…", "adapted it for VOA…", "Contributing…", "wrote this lesson…") are printed, not narrated. They are shown muted, never timed, and not sent to the aligners (`nonSpokenFlags` in `src/lib/align.ts`). Checked against Scribe's words: its last words are always the sign-off.
- Speaker labels ("CASSENDRA WALLER: “…”") are printed, not spoken: shown, never highlighted or timed, and left out of the aligned text (`speakerLabel` in `src/lib/align.ts`).
- Timing sources: Scribe v2 is primary, because it transcribes what is actually spoken. Forced alignment only fills words Scribe did not match, and only where its time lies between the nearest Scribe-timed words (`mergeAnchors` in `scripts/align/align.mjs`). Forced alignment cannot tell narration from printed text, which is why it was demoted.
- `npm run align` (`scripts/align/align.mjs`, needs `ELEVENLABS_API_KEY` in `.env`) runs ElevenLabs forced alignment and Scribe v2, maps both onto the original words, and keeps the better one by a score (coverage minus long unmatched runs). Results are in `scripts/align/report.json`. Raw API responses are cached in `scripts/align/.cache/` (git-ignored), so reruns don't call the API.
- Dictionary: hovering (or focusing) a word shows a small card with its part of speech and up to 3 short Russian translations. Data is `static/data/dictionary.json`, built by `yarn dict` (`scripts/dict/build.mjs`) from the FreeDict eng-rus release (CC BY-SA 3.0; the output is share-alike too). The build caches the source archive in `scripts/dict/.cache/` (git-ignored). Only words in the transcripts are included. FreeDict has no entries for many function words, so `scripts/dict/supplement.json` (hand-written) covers them: is/are/was, a/an/the ("не переводится"), pronouns, contractions. It also maps irregular forms to their base word (made → make). Inflected words show the base word's entries too, placed before the surface form's, so "remains" shows the verb (remain) before the noun. FreeDict sense order is imperfect (e.g. "high" lists a slang sense first). Lookup normalization is `wordKey` in `src/lib/word.ts`. Entries may carry an optional `note` (shown as a grey line on the card), used for forms of "to be" so learners recognize them. Episode titles (on the episode page and the library cards) use the same hover card via `DictWords.svelte`, which splits the title into hoverable words. Title words are included in the dictionary build. Parts of speech are shown as short Russian labels (сущ., гл., прил., арт., …) from `posLabel` in `src/lib/dictionary.ts`, so learners don't need the English grammar terms. The card uses Noto Sans from Google Fonts, because the system font placed Cyrillic stress marks on top of neighbouring letters (e.g. the breve in «й»).
- Playback uses the Web Audio API with the Signalsmith Stretch AudioWorklet (`src/lib/web-audio-player.ts`, MIT, `signalsmith-stretch` npm package). It changes tempo without changing pitch, and the position comes from `AudioContext.currentTime`, not the `<audio>` element. Gotcha: the worklet throws on chunked `addBuffers` uploads, which silences the node with no error on the page, so the whole file is uploaded in one call. Trade-off: the whole file is decoded and copied into memory.
- Settings popup (sliders button in the dock, floats above the button): "Remember position" (default on; when off, positions are neither saved nor restored) and "Forget saved positions" (clears all `voa-player:position:*` keys). Auto-scroll stays in the dock row.
- Favicon: `src/lib/assets/favicon.svg`, the four-bar logo from the header, no background, filling the square. It is inlined in the page as a data URI.
- Deployed: GitHub Pages uses the Actions source. `paths.base` is set from `BASE_PATH` in CI, and is empty locally.
- The template's `svelte.config.js` is absent. The adapter is set in `vite.config.ts`, and the build works with that.

## Data notes

- Each episode needs: audio file, official transcript text, and ideally word- or sentence-level timing for the highlight. If timing is missing, we need a way to create it (for example forced alignment), and that is a separate decision.
- Keep the collected sample set in a dedicated folder (`static/data/`), with one entry per article: title, date, source URL, audio URL, transcript source.
- Record the source of every file so licensing and provenance stay traceable.
- Layout (same for every batch): `static/data/audio/<section>/<id>-<date>.mp3` and `static/data/transcripts/<section>/<id>-<date>.txt`. One manifest, `static/data/episodes.json`, lists every episode with `batch`, `section`, title, date, paths and sources.
- Batches:
  - `special-english-2011`: 10 Sept 2011 reports from manythings.org mirror pages. Sections are the report names (economics, health, technology, agriculture, education, in-the-news). The voanews.com text links are 404 now, so the text is a mirror copy.
  - `learning-english-2025`: 137 stories, Jan–Mar 2025, from learningenglish.voanews.com (7 from the first batch, 30 added later, and 100 more). Sections are the site's section slugs ("American Stories" and "All About America" included). These are VOA's own article texts.
- Audio and transcripts are both committed (GitHub Pages serves the audio).
- Freshness: article text is readable up to about 20 March 2025. The sitemaps (`learningenglish.voanews.com/sitemap_428_*.xml.gz`) list articles only in the `/a/<slug>/<id>.html` form, and the slug is needed: an ID-only URL does not redirect and returns an empty shell. Newer articles (IDs 8,0xx,xxx and up, 2025–2026) are listed in the sitemaps, but their pages stay empty with any URL form tried, so nothing newer than March 2025 has a transcript. To find more articles, take the slugged sitemap entries and fetch them by slug.
- Themes: spread downloads across sections (Health & Lifestyle, Science & Technology, Arts & Culture, Words and Their Stories, As It Is, Ask a Teacher, Everyday Grammar). Not yet available: American Stories (newest with audio is 2017), Education Tips (page has no body text), News Words, English in a Minute, English @ the Movies, and Everyday Grammar Video (empty).
- Adding episodes (the method used for the 100 Jan–Mar 2025 items): `scripts/ingest/ingest.py` has four stages, run from the project root: `sitemaps` (slugged article list from the four sitemaps), `crawl N` (parse the newest N candidates from 2024-01-01 on, staged in `scripts/ingest/.cache/`), `select N` (newest N usable items not in the manifest; usable = body, MP3, date and section), `build` (writes transcripts, downloads MP3s, appends the manifest). Then run `npx prettier --write static/data/episodes.json`, `npm run align` (about 1 hour for 100 episodes; cached responses are reused) and `npm run dict`. Check the new batch in the manifest with `batch`, and check the sections match the existing slugs.
- Fetching: use plain curl with no custom User-Agent (a custom one gets 406). Article pages on learningenglish.voanews.com must be loaded by slug URL (`/a/<slug>/<id>.html`). The ID-only URL returns an empty shell.

## Working rules

- Do not deploy to GitHub Pages, and do not commit or push, without the user's explicit request.
- Keep the code small. Prefer the platform (browser audio, HTML/CSS/JS) over new dependencies until the player needs one.
- Audio files are committed to the repo, because GitHub Pages serves them. Keep each file under GitHub's 100 MB limit and the Pages site under 1 GB.
